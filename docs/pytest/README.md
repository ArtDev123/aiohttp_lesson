# Автотесты API — pytest

Продолжение после Celery: чеклисты `curl` становятся **тестами**. Ходят они в **отдельную** Postgres — не в ту базу, где сиды и ручной Swagger.

Роуты, репозитории и SQL настоящие. Подмен нет: если `SELECT` сломан, тест красный.

Материал разбит на этапы: теория → код → разбор → проверка.

## Как читать

1. Сначала [guide.md](guide.md) — зачем своя БД, как не задеть `library_db`.
2. Затем строго по порядку шаги ниже — не переходите дальше, пока не отметили «✅ Готово».

Каждый технический блок устроен одинаково:

1. **Задача** — что должно получиться и зачем шаг нужен.
2. **Теория** — концепции, без которых код «магия».
3. **Код** — что пишем в файлы.
4. **Разбор** — зачем каждая конструкция.
5. **✅ Проверка** — команда `pytest` и что должно гореть зелёным **сейчас**.

## Что уже должно быть

Рабочий FastAPI: `/health`, CRUD. Миграции Alembic применяются к тестовой базе из pytest — руками `make migrate` на неё не обязателен.

Celery и `/exports` нужны на шаге 5. Шаги 1–4 от очереди не зависят.

## Стек тестов

| Компонент | Зачем |
|-----------|--------|
| pytest | находит `test_*`, гоняет, считает падения |
| Postgres `library_test` | отдельные таблицы, их можно резать |
| Alembic | схема на тестовой базе |
| `TestClient` | HTTP к приложению в том же процессе |
| Celery eager | `delay()` выполняет задачу сразу, без брокера |
