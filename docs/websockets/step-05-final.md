# Шаг 5 — Финальный прогон

**Предыдущий:** [step-04-socket.md](step-04-socket.md) · **К карте:** [guide.md](guide.md)

## Задача

Один экспорт на полном каталоге: сокет показывает рост `book_count`, файл скачивается отдельно, старый `GET` статуса не сломан.

Нужны Redis, воркер с кодом шага 2, API с кодом шага 4, около 150 000 книг.

---

## 1. Чеклист

| ☐ | Проверка |
|---|----------|
| ☐ | `POST /exports` → `202`, в теле `task_id` |
| ☐ | сокет на этот id получает `PROGRESS` больше одного раза |
| ☐ | `book_count` в кадрах не убывает |
| ☐ | последний кадр `SUCCESS`, `book_count` близок к числу строк в `books` |
| ☐ | `filename` есть только в `SUCCESS` |
| ☐ | скрипт клиента завершился после последнего кадра |
| ☐ | `GET /exports/{task_id}` равен последнему кадру |
| ☐ | `GET /exports/{task_id}/file` → `200` |
| ☐ | второй сокет на уже готовый id — один кадр `SUCCESS` и конец |
| ☐ | Ctrl+C в клиенте не ставит задаче `FAILURE` |
| ☐ | чужой id — кадр `PENDING` и тишина; соединение само не падает в 404 |
| ☐ | `GET /health` и `GET /books` живы, пока сокет открыт |

Постановка и просмотр:

```bash
curl -s -X POST http://127.0.0.1:8080/exports
python scripts/watch_export.py ВСТАВЬТЕ_TASK_ID
```

---

## 2. Что покрыли

```text
POST /exports                 delay(), 202
воркер                        пачка → файл → update_state(PROGRESS)
GET  /exports/{task_id}       export_snapshot
WS   /exports/{task_id}/ws    тот же снимок, пока не конец
GET  /exports/{task_id}/file  FileResponse, не сокет
```

Цепочка:

```text
Uvicorn accept
  → to_thread(export_snapshot)
  → Redis AsyncResult
  → кадр, если снимок новый
  → SUCCESS → close
```

Воркер в этой цепочке только пишет Redis и файл.

---

## 3. Было / стало

| Тема | Опрос `GET` | Сокет |
|------|-------------|-------|
| Кто напоминает спросить статус | клиент | сервер, пока соединение открыто |
| Середина экспорта | тот же JSON, если дёрнуть `GET` | кадр `PROGRESS` сам |
| Конец | клиент замечает `SUCCESS` | кадр и `close` |
| Файл | `GET .../file` | так же, не кадр |
| Обрыв наблюдателя | ничего | задача в воркере продолжается |

Оба канала вызывают `export_snapshot`. Расхождение полей — ошибка в одном из хендлеров, не «так устроен протокол».

---

## 4. Типичные ошибки

| Симптом | Что проверить |
|---------|----------------|
| сразу `SUCCESS`, без `PROGRESS` | каталог маленький или сокет открыли после конца задачи |
| долго `STARTED` и `book_count: null` | воркер не перезапущен, в коде нет `update_state` |
| вечный `PENDING` | нет воркера, не тот Redis, или id выдуман |
| `GET` уже `PROGRESS`, сокет молчит | открыт `http://`, а не `ws://`, или не тот порт |
| API замирает на время экспорта | `export_snapshot` вызван без `asyncio.to_thread` |
| кадры с одним и тем же JSON пачкой | нет сравнения с `previous` |
| `filename` в середине | в meta прогресса положили имя; его пишет только `return` |
| файл 404 при `SUCCESS` | API и воркер смотрят в разные каталоги `exports/` (том в Compose) |
| после правки задачи поведение старое | воркер держит старый код в памяти |

## 5. Куда расти (не в этом уроке)

- Отменять задачу, если клиент прислал кадр `{"action": "cancel"}`. Сейчас сокет только читает.
- Не слать снимок с API по таймеру, а публиковать пачку в Redis pub/sub: тогда несколько процессов Uvicorn увидят её сразу.
- Таймаут на вечный `PENDING`, чтобы чужой id не держал соединение.
- Проверка в pytest: `TestClient.websocket_connect` и задача в eager-режиме. На 150 000 строк такой тест не гоняют — в `library_test` каталог маленький, там проверяют один переход в `SUCCESS`.
