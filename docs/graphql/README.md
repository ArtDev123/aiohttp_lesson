# Книги с автором и жанром — GraphQL

Продолжение после FastAPI: то же REST API остаётся. Рядом появляется **один** эндпоинт `POST /graphql`, где клиент сам говорит, какие поля книги ему нужны — в том числе вложенные **автор** и **жанр**.

В REST `GET /books` всегда отдаёт фиксированный JSON: имя автора и имя жанра строками. Биографию автора так не получить — это второй запрос `GET /authors/{id}`. GraphQL собирает дерево в одном ответе.

Материал разбит на этапы: теория → код → разбор → проверка.

## Как читать

1. Сначала [guide.md](guide.md) — зачем схема, чем запрос отличается от `GET /books`, где живёт сессия.
2. Затем строго по порядку шаги ниже — не переходите дальше, пока не отметили «✅ Готово».

Каждый технический блок устроен одинаково:

1. **Задача** — что должно получиться и зачем шаг нужен.
2. **Теория** — концепции, без которых код «магия».
3. **Код** — что пишем в файлы.
4. **Разбор** — зачем каждая конструкция.
5. **✅ Проверка** — команды / `curl` / GraphiQL: что должно работать **сейчас**.

## Что уже должно быть

Рабочий FastAPI: CRUD книг, `BookRepository` с `selectinload(Book.author)` и `selectinload(Book.genre)`, сиды. Именно этот репозиторий отдаёт книгу, у которой автор и жанр уже в памяти — GraphQL их только раскладывает по полям схемы.

Celery, Redis и pytest для этого гайда не нужны. Docker не обязателен: локальный `python -m app.main` достаточен. Если API крутится в Compose — на шаге 4 образ надо пересобрать, пакет попадает в контейнер только так.

Клиент задачи 1 (`task_1_client`) не трогаем.
