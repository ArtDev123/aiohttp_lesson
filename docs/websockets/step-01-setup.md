# Шаг 1 — Клиент сокета и живой воркер

**Предыдущий:** [README.md](README.md) · **Следующий:** [step-02-progress.md](step-02-progress.md)

## Задача

Поставить библиотеку, которой вы будете **слушать** сокет, и убедиться, что экспорт на 150 000 книг вообще доезжает до `SUCCESS`. Маршрута `WS` ещё нет. Серверу FastAPI отдельный пакет для WebSocket не нужен: его даёт Starlette, она уже стоит вместе с FastAPI.

---

## Теория: кадр, не ответ HTTP

HTTP-запрос живёт до одного ответа. `GET /exports/{task_id}` — один снимок и соединение закрыто. Чтобы увидеть следующий `book_count`, клиент открывает запрос заново.

WebSocket после рукопожатия (это всё ещё HTTP `Upgrade`) остаётся открытым. Сервер пишет в него несколько сообщений — **кадров**. Каждый кадр у нас будет JSON одного снимка. Порядок кадров — порядок записи. Клиент не спрашивает «ну что там?», он читает поток.

`curl` кадры не читает. Для проверки ставим клиент `websockets`. В `app/` его не импортируем.

---

## Теория: почему на трёх книгах нечего смотреть

Задача читает каталог пачками по 1 000 строк. Три сидовые книги — одна пачка и сразу `return`. Сокет успеет показать разве что `SUCCESS`.

`app/seed.py` доливает книги до **150 000**. Повторный запуск ничего не добавляет, если столько уже есть:

```bash
python -m app.seed
```

Строка `Сиды уже есть (150000 книг), пропускаем.` — норма. Если книг меньше, скрипт допишет разницу пачками и напечатает прогресс каждые 10 000.

## 2. Воркер и один экспорт

Два терминала, как в гайде Celery. Redis и Postgres уже запущены.

```bash
celery -A app.celery_app worker --loglevel=info
```

```bash
python -m app.main
```

Поставить задачу и дождаться конца опросом. Сокета ещё нет — этот шаг только проверяет, что 150 000 книг воркер осилит.

```bash
curl -s -X POST http://127.0.0.1:8080/exports
```

Из ответа возьмите `task_id` и повторяйте:

```bash
curl -s http://127.0.0.1:8080/exports/ВСТАВЬТЕ_TASK_ID
```

Сейчас, до шага 2, середина выглядит так: долго `STARTED` без `book_count`, потом сразу `SUCCESS` и число около 150 000. Это ожидаемо. Промежуточный счётчик появится, когда задача начнёт писать его в Redis.

Файл:

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  http://127.0.0.1:8080/exports/ВСТАВЬТЕ_TASK_ID/file
```

`200` — файл лежит. Не читайте его целиком в терминал: это весь каталог.

Если API в Compose, воркер — сервис `worker`, не процесс на хосте. `POST` ходят на опубликованный порт `8080`.
